Work · 04

aes · 员工群

一群有独立人格、独立岗位、独立上下文的员工， 坐在同一块群板上开会。单聊是「同事」，不是「每次重新认识的客服」。 整个系统零依赖：只用 Python 标准库。

为什么是「群板」

共享一块板，不互发消息

员工之间不是点对点聊天，所有的发言落在同一块板上。开会就是往板上写，各自读。

员工只吃切片

上下文按岗切成固定片（默认 6000 字符），而不是让每个人重读全史。 成本结构决定了会议能不能开得久。

进度就是工具调用

LLM 没有中间状态可汇报。界面上看到的「进度」， 是它此刻在调用什么 —— 观测已经发生过的事，不让模型预测。

硬预算，到线下班

单次开会与每日花费都有上限。超了中止并如实记账，不静默继续。 值班是无人看管账单的唯一刹车。

手和网都被收着

  • 工具只读。读文件、列目录、搜内容；路径锁死在白名单根目录里，没有写、没有删。
  • 网只出。只 GET、只 http/https、只公网；重定向逐跳过闸。
  • SSRF 闸不是假想防护。禁打本机、内网、链路本地 —— 员工是模型驱动的，它可能被某份网页里的指令骗着去撞本机的服务。

怎么跑

# 谁在岗
python3 run.py list

# 开会
python3 run.py meet "任务描述" --rounds 2

# 基站：常驻服务 + 界面
python3 run.py station   # → 127.0.0.1:8848

另有一个 macOS 桌面壳 aes.app： WKWebView 打开本机界面，基站没起来就自己拉起来， 窗口关了壳退、基站继续值班。
